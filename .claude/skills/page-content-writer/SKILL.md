# Page Content Writer

Build content for a web page that has two jobs at once, getting found in search and converting the reader. This skill is fully self-contained. It owns the PAGE METHOD (the four phases below) and the SENTENCE-LEVEL WRITING RULES (the section directly beneath the non-negotiables). It depends on no other writing skill. Obey both layers on every word written here.

## Rules for this skill

private/core-rules.md governs all behavior and writing, and the hook loads it every turn. Follow it in full. This skill does not repeat it. Below are only the writing rules specific to a page that are not in core-rules. Obey these together with core-rules.

1. **Use prescriptive commands sparingly.** "You should," "you must" and "you need to" are listed in the owner's banned terms file under the heading "Use Sparingly", not under an outright ban. Prefer "tends to work," "often works well," or "works well," because the owner guides rather than commands. Where a command is genuinely the clearest thing to write, it is his call and not an automatic failure. Corrected 2026-08-03 after the skill was found to be stricter than his own file.

2. **Never repeat a distinctive key word across a set.** Within a group of bullets, or across the sections of one page, do not reuse the same content-bearing word, meaning a noun, verb, or adjective that carries the meaning (for example "competence" in two bullets), as opposed to common function words like "the," "your," and "and." Vary it or cut one.

3. **Substance test, run on every sentence.** A sentence is not cut merely for being common. Keep or cut each sentence by the result of these two questions:
   1. Name the specific thing it tells the reader. It must be one of these: a fact, a number, a cause and its effect, or an instruction the reader can act on.
   2. Name why that thing is true, or how it works, in one further sentence.

   Decision:
   - Name both: keep the sentence.
   - Name the thing but not the reason: keep the sentence and add the reason.
   - Name neither: cut the sentence.

   Kept example. "Good lighting defines your features." The thing is that lighting shapes how the face reads. The reason is that it reveals bone structure and controls shadow. Both are nameable, so it stays, even though it is common.

   Cut example. "Your headshot carries real weight." There is no specific thing and no reason to name, so it is cut.

   This generic-filler problem is part of why his pages were de-indexed, so the test is not optional.

## The method: four phases in order

Do not skip a phase. Do not write in Phase 1 or 2. Writing happens only in Phase 3.

### Phase 1 — Research (before a single word)

Gather the facts the page must be built on. Nothing here is creative.

1. **Read the page's written job first, then the page in full.** The job is written in `private/PAGE-JOBS.md` in the owner's own words and that file is the only source of it. Never invent a job and never infer one from the page's name. A page with no job written there is not worked on. The job decides which frameworks apply, per FRAMEWORK-SELECTION.md, so it is read before anything else. Added 2026-08-03, because this method never named that file. Then read the target page in full and know what already exists, what is real, and what is placeholder.
2. **Read the page template and the sibling pages, named explicitly.** Service and profession pages are built from the hardcoded template `src/pages/business-headshots.astro` (it carries the full `Props` interface plus the hero, pillars, system rows, testimonials, and FAQ structure). The sibling service and profession pages are `src/pages/acting-headshots.astro`, `src/pages/linkedin-headshots.astro`, and `src/pages/office-headshots.astro`. Location pages are a SEPARATE type built from the `src/components/Hero.astro` component: `src/pages/york-headshots.astro`, `philadelphia-headshots.astro`, `baltimore-headshots.astro`, `harrisburg-headshots.astro`, `delaware-headshots.astro`, and `conference-headshots.astro`. Read the template in full, plus at least two siblings OF THE SAME TYPE as the page being built, to learn the structure and the owner's voice.
3. **Check for cross-page duplication, and apply the rule for THIS page's type.** The two page types have OPPOSITE duplication rules (SEO guide, "Duplicate Content on Service Area Pages"):
   - **Location pages** (same service, different city): reusing the core content with the location details swapped is allowed and often works well. But a location page may also need fresh content, and writing it fresh is allowed when the page calls for it. Neither is forbidden.
   - **Profession and service pages** (same area, different audience, for example lawyers vs business vs acting): each page must be genuinely specific to its profession. A section that repeats verbatim across these siblings (commonly the "process" or "experience" section) is redundant duplicate content and must NOT be copied again. For each such slot, either make the section genuinely specific to this profession, or replace it with something unique to this profession. Default to making it specific; replace the slot only when nothing profession-specific belongs there.
4. **Pull real search intent from Search Console** using the `mcp__gsc__search_analytics` MCP tool. Use `siteUrl: https://richardwainephotography.com/` (the non-www property). Set `startDate` to the earliest date GSC retains (16 months before today) and `endDate` to today, so the full retained window is captured. Set `dimensions: query` and pass a regex over the page's topic via `queryFilter` with `filterOperator: includingRegex`. This returns every term the page's topic has earned an impression on across the full retained history, which is the complete discovery set. The full window alone cannot tell a live term from one whose demand has died, so run a second pull for the most recent 3 months (same `dimensions`, `queryFilter`, and `filterOperator`) and compare the two. Run the intent regex patterns from `private/SEO Strategy & Guides/gsc-regex.md` against the pulled queries to sort them by intent. This step is mandatory. Do not categorize queries by eye or judgment. Apply each pattern from that file verbatim, never altered, and replace any placeholder such as the brand name or city with the real value before running it. A query's intent is the category whose pattern it matches. Select the target terms as follows: first group the discovery-set queries by the SINGLE search intent this page serves (per the guide's "one page, one intent"); drop any term that earned impressions in the older history but recorded zero impressions in the recent 3-month pull, because that demand is gone; from what remains, target the terms with the highest combined impressions; give priority to terms where the page or site already ranks within striking distance (average position 20 or better) because those are winnable, while still keeping high-impression terms the page does not yet rank for. The resulting group may differ from the term assumed at the start.
5. **Gather any needed stat or quote, traced to a primary source.** Allowed sources are primary and independent only: peer-reviewed studies, government data, recognized research firms. NEVER use another photographer, a photography company, a competitor, or social media. They are unreliable, untrusted, and the owner likely knows who they are. Before using any stat or quote, grep the repository content (the `src/` directory) for the figure and for the source name, and confirm the owner has not already published it anywhere on the site. An overused or already-published source is dead.
6. **Consult the SEO guide for best practices.** The guide lives at `private/SEO Strategy & Guides/SEO Guide For Claude.md`. It is a living document that grows over time as the owner feeds in trusted sources via the seo-video-ingest skill, so always work from its CURRENT Table of Contents, never a memorized list of sections. Do NOT read the whole guide (it is thousands of lines). Read the Table of Contents fresh each time, identify every section relevant to this page, and grep/read only those. Relevant sections typically include content structure and GEO, E-E-A-T and trust signals, content red-flags to avoid, SEO copywriting and search intent matching, duplicate content on service-area pages, high-intent compact pages, service variation pages, and the PAA FAQ method, but treat these as examples and scan the live TOC for anything else that applies. The page content must accommodate the best practices found there.

7. **Consult the Content Frameworks for conversion principles.** The frameworks live at `private/Content Planning/Content Frameworks/`. Each subdirectory contains a knowledge base and prompts file from a proven copywriter or marketer (Hormozi, Ogilvy, Schwartz, Kennedy, and others). Read the knowledge files for every framework relevant to this page's conversion job (e.g., Hormozi's value equation for structuring the offer, Schwartz's awareness levels for matching the reader's stage, Ogilvy's research-first principles for credibility). Apply the relevant conversion principles to how the content is structured and how it moves the reader — but always subordinate to the owner's brand rules. Selling, urgency and scarcity are PERMITTED. Force is not. The owner ruled 2026-08-02 that he wants a visitor treated the way he wants to be treated when shopping, which is not being forcefully sold to. The technique is fine, the pressure is not, and language and tone decide which one a line is. The frameworks inform the thinking, not override the voice.
8. **Learn the owner's voice from existing material, and mine it before asking anything.** Before drafting, read the owner's existing pages and blogs to internalize voice and meaning, and read the Brand Voice Guide in the owner's Google Drive (the "AI Knowledge Base" folder, accessed via the Google Drive MCP). Draw needed substance from that material first. Only after mining it, ask the owner specific, targeted questions about genuine gaps. Never interview cold. Ask each question in plain language. Ask directly for what you need to know, with no poetic, flowery, or decorative phrasing. A question is a request for one specific fact or experience, nothing more. NEVER copy the owner's wording from one surface onto another. Learn the meaning, then write original copy for this page. Every surface gets its own words.
9. **Load the owner's banned terms and cliché rules.** Read `private/BANNED-TERMS.md` and the banned words in the Brand Voice Guide (Google Drive "AI Knowledge Base" folder, via the Google Drive MCP) before drafting. Also avoid industry clichés the owner rejects (for example, the "first impressions" concept, not just the phrase). These are in addition to the Sentence-level writing rules section above and the full list in BANNED-TERMS.md.

Output of Phase 1: a short, factual brief. The real structure, the duplication map, the main search terms to target, any verified stat, the relevant best practices pulled from the SEO guide, the conversion principles pulled from the Content Frameworks, the banned terms, and notes on the owner's voice. No prose. This brief is internal working product. It is not presented to the owner and is not an approval gate. The first thing presented for the owner's approval is the Phase 2 map.

### Phase 2 — Map (before drafting)

1. List every element the page needs, in the order the template for this page's type lays them out, which for a service or profession page is hero, the three pillars, the system rows, testimonials, FAQ, and close.
2. For each element, write ONE line stating the exact job it does: which search intent it captures, or which conversion job it serves, or both.
3. If an element cannot name a real job, cut it. Forcing sections or bullets to fill a slot is a primary failure.
4. Do not set a length target. Length is not tied to search intent. Write in full sentences (no fragments) with no padding, no filler, no AI slop, and the content will answer the query and the intent on its own. Let the length fall where it falls. Never pad to reach a size, never cut substance to be brief.
5. Present the map. Get explicit approval before any writing.

### Phase 3 — Build, one element at a time

For each element, in order, follow this loop:

1. **Header:** every header tag is the keyword or keywords pulled from a real search term that appeared in the Phase 1 Search Console pull, formed to address that search's intent. Users often search in full sentences or questions. Never use a full sentence or a question as a header. Pull the keyword or keywords out of the search term and build the header from them, so the header addresses the intent that query carries, which is its category from the Phase 1 intent grouping. The keyword must come from a term that appeared in the Search Console pull. If it is not in that data, it is not verified and cannot be used. The header makes no promise the section cannot keep. Maintain correct HTML heading hierarchy: one H1 per page (the page's primary term), section headers are H2, subsections H3, never skip levels.

   **Hero element:** there are two hero types.
   - **Entry-point pages** (the homepage and the location pages) get a display tagline of three stacked short phrases plus a separate H1 that is the page's search term. Example from the York page: tagline "WORLD CLASS", "HEADSHOT", "EXPERIENCE", and H1 "Professional Headshots York".
   - **Service and profession pages** (business, acting, linkedin, office, lawyer) do NOT get the display tagline. Their hero is just the H1, which is the page's keyword. Example from the business page: "Business Headshots".
   Both types carry one short description paragraph in the owner's voice (a real point of view, never hype), two button labels, GET PRICING and SCHEDULE CONSULT, and on service and profession pages a "Sessions available in" line naming the location areas: Lancaster PA, Philadelphia, Baltimore, Harrisburg, York, and Delaware. On the portrait, two one-word callouts tied to the page's theme (example from the business page: CONFIDENCE, APPROACHABILITY); omit them only if no single words fit.
2. **Body:** write in the owner's voice, full flowing adult prose (never choppy or staccato), every claim sourced. Apply the Sentence-level writing rules in full. Hold these positioning rules on every element:
   - **StoryBrand:** the reader is the hero, the owner is the guide. Heavy "you." The owner is a solo operator, so NEVER use "we" (there is no team, it is one person making every photo). "I" is correct and authentic when referring to the owner doing the work; do not scrub it. NEVER write a section that justifies why the owner matters or why they are important. A "why a specialist" or "why me" section breaks this and is forbidden.
   - **Relationship sequence:** content moves the reader along connection, then rapport, then familiarity. Never jump to a transactional ask. The page educates and builds trust; the booking follows.
   - **Protect the private technique:** describe outcomes only. Never publish or hint at the owner's behind-the-scenes method for eliciting expressions. Outcome-level concepts only, never the how.
   - **Citable by AI (default, not a straitjacket):** where the format and natural phrasing allow, open a section or an FAQ answer with a direct, self-contained answer to the question it addresses, so AI engines can cite the sentence that cleanly answers the query, with detail following. This is the default, NOT an absolute. Never force a stiff "answer-first" sentence that reads unnaturally or breaks the owner's voice. Natural phrasing and voice win; apply the pattern only where it fits.
3. **Bullets (if the element uses them):** bullets REINFORCE the content, they never repeat it. A bullet that restates what the prose already said is filler and must be cut or replaced. Each bullet either reinforces with a NEW point or carries a verified stat. Bullets are POINTS, not sentences. No two-part structures. No commas. Keep each one tight and singular. Match the existing bullet style (no trailing punctuation if siblings have none).
4. **FAQ (when building it):** questions come from real searched questions, never invented. Source them from GSC FIRST and primarily, because GSC reflects actual searches where the owner's site already earned an impression or click. Only as a last resort, when the GSC pull returns no question-form queries for the topic, fall back to the existing Topical Authority Map (`private/Content Planning/TOPICAL-AUTHORITY-MAP.md`), and beyond that run the People Also Ask Scraper located at `/Users/richardwaine/CloudStation/People Also Ask Scraper/paa-scraper`, invoked as `node scraper.js "<keyword>" [depth] [delay_ms] [output_dir]` (defaults: depth 3, delay 3000 ms, output `./output`), then add the results to the map so the work compounds. Phrase questions the way people actually search them. Each answer leads with a direct, complete answer in the first sentence or two, then any detail. Answers feed the same `faqs` array that drives the FAQ schema.
5. **Close / CTA (when building it):** the owner does not hard-sell, and the existing pages prove it. The page educates, informs, and lets the work speak; the booking follows from trust, not a push. Keep any call to action quiet and singular, one simple next step sitting there for the reader who is ready. Never stacked asks and never pressure. Urgency and scarcity are permitted, ruled by the owner 2026-08-02, so a real constraint may be named plainly. What is banned is force, and tone decides which one a line is. Corrected 2026-08-03, because this sentence still carried the old blanket ban thirty lines below the ruling that replaced it. Match the tone of the CTAs already on the owner's pages.
6. **Self-check** against every rule in this skill, including the Sentence-level writing rules, before the user sees it.
7. **Present that ONE element, finished.** Show it exactly as it will read on the page: header, body, and bullets, in full, never truncated. Above it, one short line stating what it is and where it goes (cite the file and line numbers when pointing at the page). Nothing else: no options, no menus, no analysis, no commentary, no explaining the choices, no selling the work. The user reads it and responds. If the user corrects, change only what they point to and re-present that one element. Do not start or touch the next element until told.

8. **Whole-page coherence pass (after every element is approved).** Read all approved elements top to bottom as one piece. Confirm no two sections make the same point, the wording flows, and the target search terms are covered across the page without stuffing. Fix any repetition or conflict in the words, then present the corrected element.

### Phase 4 — Finish the content

Only after every element is approved.

1. Use the real search terms in the title and H1. Do NOT hand-write the meta description; use the meta-description-writer skill, which is proven to lift CTR. Do NOT hand-write image alt text; use the image-seo skill. For the URL slug, PROPOSE one and let the owner decide. Never change a URL slug on your own.
2. **Schema:** match the schema already on sibling pages. Do exactly what those pages do, nothing invented. Import and call the existing builder functions in `src/utils/schema.ts`. NEVER hand-write JSON-LD. For a service or profession page the established set is `buildServiceSchema` once, `buildReviewSchema` once per testimonial shown, and `buildFAQSchema` once. The FAQ schema must be fed by the SAME `faqs` array that renders the on-page FAQ, so the visible FAQ and the schema never drift. If a page genuinely needs a type no existing builder covers, follow the established pattern, add the builder in the same style, and tell the owner what was added.
3. **Internal links:** follow the owner's internal-linking SOP in the SEO guide (`private/SEO Strategy & Guides/SEO Guide For Claude.md`, the Internal Linking section). Read that section every time, as it is the source of truth and may change. Its key moves: link FROM an already-ranking page TO the new page (cornerstoning), keep at least one link to an important page as insurance, cap in-body links at 5 per page, and remember a new page's own links do not pass authority until it ranks. The guide governs; this summary never overrides it.

## What this skill is NOT

- Not a blog writer. Blogs are educational long-form; use blog-writer for those.
- Not a place to invent topics to fill space. Demand from the data drives sections.
- Not permission to write in Phase 1 or 2, or to move ahead without approval.
- Never puts the page live. Publishing is the owner's decision alone.
